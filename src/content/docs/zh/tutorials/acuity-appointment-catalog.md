这个提示模板改编自观察到的用户工作流。结果取决于你的账号和当前页面。修改之前先检查对比结果，并在网站上核对已保存的内容。

当你想把现有的预约目录和已批准的主清单对比，再创建一小批缺失的预约类型时，用这个流程。

## 开始之前

第一次用 dassi？先看[安装指南](/zh/getting-started/installation/)和[模型设置指南](/zh/guides/connect-ai-provider/)。

在 Chrome 里打开你的 Acuity Scheduling 账号，旁边打开 dassi。为每个要添加的预约类型准备好准确的名称、时长、价格、描述、日历和可见性。先从一个地点的三条开始。平台设置见 Acuity 的[预约类型指南](https://help.acuityscheduling.com/hc/en-us/articles/16676922487949-Creating-and-editing-appointment-types)。

## 1. 找出缺失的条目

```text
把我已批准的主清单前三条和我打开的这个 Acuity 账号里的预约类型做对比。

业务/地点：[地点]
主清单：[每条的名称、时长、币种和价格、描述、日历、可见性]

返回一张对比表：完全匹配、疑似重复、缺失、无法确定。有差异的地方显示当前值。先不要创建、编辑或删除任何东西。如果某个必填值或日历分配不清楚，停下来。
```

疑似重复的条目要人工检查。名字相同不一定是同一个地点或日历。

## 2. 创建审核过的一批

```text
只创建这些审核过的缺失预约类型：[已批准的条目及全部设置]。严格使用提供的值。不要修改或删除现有的类型、预约或其他账号设置。
重新打开每个创建的预约类型，把每个要求的字段和保存的值对一遍。每条返回一行：已创建并核对 / 部分完成 / 未完成，附差异和页面链接（如有）。这一批做完就停。
```

## 3. 核对面向客户的设置

检查保存的名称、时长、价格、描述、分配的日历和预期可见性。查看相应的预约页面，但不要真的下预约。可预约时段要单独核对：预约类型保存成功不代表客户就能预约到预期的时间。

Acuity 提到，新建的预约类型可能还需要加入相关的套餐、礼品券或订阅。在宣布服务可供客户使用之前，单独检查这一点。

如果中途被打断，把最后一张结果表给 dassi，让它在再创建任何东西之前先重新检查账号。疑似重复项的删除不在这个流程里；先把不确定的条目理清再行动。
